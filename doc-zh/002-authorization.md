# 002 授权

> 原文版权：Copyright (c) 2026 DeepSeek Harness Team；MIT License。
> [英文原文](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/docs/002-authorization.md) · 固定版本：`6337fc823ce20251c8de8085948165c81aaa701e`  
> 中文翻译，非官方；代码与配置保持原样。

授权决定谁可以发起工作，以及这项工作可以包含哪些内容。本文建立在 [001 领域模型](001-domain.md) 之上。

宿主负责强制执行允许名单、规则和授权。消息、评论以及被引用的文档都是决策输入，不能改变这些权限。

<a id="two-paths-for-a-trigger"></a>

## 触发的两条路径

<a id="eval-deciding-whether-to-start-work"></a>

### 评估：决定是否开始工作

来源会记录消息是否面向 Agent：提及机器人或 Agent 账号时记为 `mention`，私信记为 `direct`。准入层检查发送者和来源的策略：

- 允许名单上的人向 Agent 发出消息，构成明确请求。
- 人在已有工单的线程中继续发言，遵循下文的规则。
- 其他人的消息使用其接收范围对应的准入表。
- 来源机器人名单上的机器人可以产生推断候选，但绝不能产生明确请求。其他机器人不予准入。

<a id="subscriptions-continuing-existing-work"></a>

### 订阅：继续已有工作

已订阅线程中的每条消息，都会作为上下文送达订阅它的工单，包括机器人和 CI 的消息。这种投递绕过准入层，不授予任何新权限。每个工单仍受自身授权限制。

人在工单自身线程中发出的消息，交由该工单的执行器判断。主 Session 将消息附加到某个工单时，也适用同样的规则。在执行器拥有该消息的处理权期间，消息不经过评估，也不产生决定。每个执行器要么在工单范围内处理请求，要么将它退回，以便路由到其他地方。

只要工单尚未结束，消息的处理权就继续有效，即使人移除了相应订阅也是如此。它也覆盖这样的情况：工单已经结束，但并非被人要求停止，且该消息正在等待使它恢复。

主 Session 会收到后续消息通知。在执行器拥有消息处理权期间，主 Session 只能应人的请求停止工作；接单、附加、忽略和重新入队都会被拒绝。停止操作仍须通过准入层，并使用下文所述的后续消息强度。

<a id="handing-back-and-releasing-follow-ups"></a>

### 退回和释放后续消息

当消息要求的工作超出工单范围，或者属于另一个工单时，执行器会将消息退回一次。工单仍保留订阅。如果附加的线程与工单无关，执行器会退回自己在该线程中拥有处理权的消息。

只有在没有任何工单仍拥有某条消息的处理权后，该消息才会进入一次新的评估。它对应的候选会包含各执行器退回消息的理由。准入层把它视为该线程中的普通消息，主 Session 可以接单、将它附加到其他地方，或者忽略它。退回工单并不拥有处理权的消息，例如机器人消息或人已经送去评估的消息，不会使任何内容入队。

工单结束时，会释放执行器没有读取或接手的后续消息。这些消息包括从未送达执行器的消息，也包括在执行器最后一次报告或回合结束后才送达的消息，前提是执行器既没有确认、回答，也没有退回它们。每条释放的消息会在没有其他工单拥有其处理权后进入评估。停止操作只结束被停止工单的工作。

已停止的工单不会把要求它停止的消息再次送入评估，除非另一个工单退回了这条消息。停止该工单的主 Session 可以将同一条消息中的其余部分接为新工作。

人可以从面板把一条仍由工单拥有处理权的后续消息送入评估。如果主 Session 随后又把它附加到一个尚未结束的工单，执行器会再次收到它。如果没有有效判断覆盖该消息，面板也提供重新评估入口。

<a id="context-only-subscriptions"></a>

### 仅供上下文使用的订阅

执行器可以关注相关线程，例如另一个 Issue 或拉取请求，以获取上下文。其中的消息会到达工单，但不会赋予权限，也不会获得后续消息的强度。那里的人类消息不会恢复已结束的工单，除非主 Session 附加了来自该线程的一条消息。主 Session 关于其他工作的备注也只作为上下文。

没有到达任何工单的人类消息会走评估路径，包括工单已被人要求停止的线程。机器人消息会独立走评估路径，无论它们是否也被投递给了订阅工单。

<a id="strength"></a>

## 强度

| 强度 | 情况 |
| --- | --- |
| explicit（明确） | 允许名单上的人向 Agent 发出消息，或在已有工单的线程中继续发言；准入表中的某个单元格设置为明确请求 |
| inferred（推断） | 不在允许名单上的人在已有工单的线程中继续发言，除非其准入表单元格为 explicit；准入表中的某个单元格设置为推断候选；来源机器人名单上的机器人向 Agent 发出消息，或在来源接收全部消息的范围内发言 |
| not admitted（不予准入） | 其他所有机器人的消息、准入表设为忽略的所有内容，以及接单模式为 `off` 时的所有推断情况 |

对于不在允许名单上的人，即使线程已有工单，设为明确请求的准入单元格仍然优先，而且在所有接单模式下都生效。否则，其后续消息为推断强度，在 `off` 模式下不予准入。对于仅为上下文而关注的线程，消息使用准入表，而不是后续消息强度。

<a id="admission"></a>

## 准入

每个来源的策略都有一张准入表。表中的行对应接收范围：

- **飞书：** 每个已配置的群聊、机器人能收到提及消息的其他群聊，以及私信。只有在飞书卡片上将 **其他群** 设为 **仅 @**，才会接收其他群聊的消息。
- **GitHub：** 新 Issue、新拉取请求、评论，以及默认分支的 CI。

每行最多有三个单元格。每个单元格决定消息会成为明确请求、推断候选，还是不产生任何内容：

| 单元格 | 可选值 | 默认值 |
| --- | --- | --- |
| 在允许名单上，但未向 Agent 发出消息 | inferred、ignore | inferred |
| 不在允许名单上，但向 Agent 发出消息 | explicit、inferred、ignore | ignore |
| 不在允许名单上，也未向 Agent 发出消息 | inferred、ignore | ignore |

针对未向 Agent 发出消息的单元格，仅在来源会接收全部消息的范围中可用，例如设为 **全部消息** 的飞书群聊，或已开启接收全部消息开关的 GitHub 范围。CI 结果没有发送者，因此对应的行只提供最后一个单元格。机器人消息使用机器人名单，不使用这些单元格。

将“不在允许名单上，但向 Agent 发出消息”这一单元格设为 explicit，意味着该范围中的任何人都可以通过提及 Agent 来请求工作。这对专门的支持群聊可能有用。推断候选仍受接单模式约束。后续消息通常绕过这张表，但 explicit 单元格仍然可以赋予明确强度。

准入表是策略版本的一部分。降低某个单元格的权限，不会立即停止此前通过该单元格接单的进行中工单。但这些工单恢复前重新验证授权时，授权可能因此被撤销。

<a id="bots-and-automated-reviewers"></a>

### 机器人与自动化审查者

宿主会将 GitHub Apps、登录名以 `[bot]` 结尾的账号，以及飞书机器人识别为机器人。来源可以列出 `dependabot[bot]` 之类的机器人，允许它们的消息成为推断候选。这些机器人必须向 Agent 发出消息，或者在接收全部消息的范围中发言。它们不能提出明确请求，也不能停止工单。

使用普通账号的自动化审查者，在宿主看来属于人。它的评论会到达订阅工单，并产生后续消息通知。团队提示词必须说明哪些账号属于自动化审查者。

<a id="routing-candidates"></a>

## 路由候选

主 Session 使用 `orchestrator_route` 路由明确候选。一次调用可以包含多个接单、附加、停止或忽略决定。各项独立处理：某项被拒绝或缺少字段，不会妨碍其他项执行。

推断候选通常需要完整研判。有一个快捷路径：如果候选卡片显然不涉及任何已启用规则，例如纯聊天或无关讨论，主 Session 可以直接忽略它。决定会记录 `ignoredFromCard`，以区别于经过规则研判后的结果。主 Session 从自身提示词的策略区段读取已启用规则。

接纳推断候选始终需要研判。直接接单会拒绝准入层未判定为明确请求的触发。

<a id="accept-mode-and-rules"></a>

## 接单模式与规则

接单模式是策略的一部分：

| 模式 | 效果 |
| --- | --- |
| `off` | 任何推断情况都不会成为候选，例如未向 Agent 发出的消息、机器人的消息，或不在允许名单上的人的后续消息 |
| `observe`（默认） | 对推断候选进行研判；正向研判结果记录为 ignore，并标记“would accept”（本来会接单），实际不接单 |
| `auto` | 对推断候选的正向研判会使其被接单 |

明确请求在所有模式下都生效。应先从 `observe` 开始，在审阅已记录的决定后再切换到 `auto`。每次研判都恰好判断一次每条已启用规则，无论规则是否匹配。主动接单至少需要匹配一条规则。

每条规则描述一种主动工作。工单的授权会记录匹配的规则，执行器会收到这些规则的名称和指令。

对该工单而言，规则中的流程和沟通要求优先于默认要求。静默规则可以禁止发送确认消息；审查规则可以指定所需的审查者，以及合并前必须获得的批准。适用于每个工单的要求，则应放在团队提示词区段中。

<a id="policy-version"></a>

## 策略版本

规则、接单模式以及各来源的策略共同构成策略版本。每份授权都会记录其接单时所依据的版本。

版本变化会丢弃正在运行的评估，并将对应触发重新入队。同时，它还会向每个受影响的进行中工单发送一条 policy-changed 输入。该输入会说明以下哪种情况发生了：

- 某条匹配规则发生变化，并附上新的规则文本，或者该规则不再适用；
- 请求者不再有权发起工作；或
- 不再接纳主动工作，例如模式从 `auto` 改为了其他值。

不受影响的工单不会收到通知。策略变化不会立即撤销进行中工单的授权。

来源配置与策略是分开的。来源配置控制什么能进入系统：读取哪些群聊，以及某个范围是接收全部消息，还是只接收提及。授权会记录其来源和接收范围。恢复工单要求来源仍在监听该线程，但不要求来源仍然接收该线程中的全部消息。

来源关闭时，回复会等待。如果来源不再监听回复目的地，则丢弃回复。

限制执行器如何处理自身结果的条件，例如何时可以合并，不决定谁能授权工作。这类条件属于 Agent 指令，不属于策略。

<a id="resume-and-stop"></a>

## 恢复与停止

已结束的工单保留其授权。人在工单自身某个线程中发送消息，就可以恢复同一项工作，无需新的评估或决定，也不取决于发送者是谁。机器人和 CI 不会唤醒已结束的工单。执行器判断请求是否符合范围；如果不符合，就结束这一轮。

只有三种操作会改变授权：接单创建授权、人要求停止会撤回授权，而重新验证失败会撤销授权。被人要求停止的工单保持结束状态，不再接收任何内容。在该处请求开展工作，需要重新接单。

<a id="revalidation-before-resume"></a>

### 恢复前重新验证

来源必须仍在监听原始线程。其余检查取决于授权的依据：

- 基于明确后续消息的授权会通过验证。
- 推断授权要求处于 `auto` 模式，且其匹配规则仍然启用。
- 通过表中单元格准入的授权，必须在当前准入表和发送者名单归属下，仍获得至少与原来相同的强度。因此，将发送者从允许名单移除，可能撤销通过“在允许名单上”单元格接单的授权。
- 机器人的授权要求该机器人仍在来源的机器人名单上。基于准入表和机器人的推断授权，还要求处于 `auto` 模式，且匹配规则仍然启用。
- 其他授权要求发送者仍在来源的允许名单上。

如果重新验证失败，工单保持结束状态，不接收任何等待中的消息。每条消息都按“未到达任何工单”处理；如果没有其他工单拥有其处理权，就送入评估。主 Session 不会收到“该消息已到达 worker”的通知。处理暂停之后也适用这一规则。向该工单附加消息会被拒绝；要继续工作，必须重新接单。

- **人在某个线程中说“停止”，是一个普通触发，** 由评估作出停止决定。执行器不能自行声明有人要求它停止。
- **面板中的停止是一个命令。** 它直接作用于工单，并记录为手动停止。
- **等待条件属于来源。** “连续 N 小时无人指派”这类条件，应由一个来源自行等待并再次检查；评估永远不等待。

<a id="when-eval-does-not-finish"></a>

## 评估未完成时

时间限制从候选到达主 Session 时开始计算。等待投递的时间不计入，未投递的候选永远不会过期。

过期的评估会把其触发重新入队，再尝试一次。连续重试两次后，第三次过期会记录为 `unavailable`。研判失败也会记录为 `unavailable`；后来的触发可以启动新的评估。策略变化，或基于过时策略作出决定，都会记录为 `unavailable`，并立即把该批次按当前版本重新入队。

`evals` 健康条目会报告最近一小时内尚未解决的 unavailable 决定。`scripts/dsh-superagent status` 也会包含这一错误。

只有在以下条件同时满足时，面板才会请求人关注：unavailable 决定距今不足 24 小时，仍是该线程上的最新决定，尚未被忽略处理，而且线程既没有排队等待评估，也没有正在评估。人可以再次评估该触发，或将这个问题标记为无需再处理。
